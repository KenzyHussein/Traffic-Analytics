======================================================================
 PHASE 5 - AZURE STREAM ANALYTICS QUERY
 Job: asa-traffic-realtime
======================================================================

WHAT THIS QUERY DOES
--------------------
- Reads streaming events from the Event Hub input alias   : [traffic-input]
- Classifies each event into an anomaly_type + severity   (CASE statements)
- Filters OUT normal traffic  (WHERE anomaly_type <> 'NORMAL')
- Writes the anomalies to the Azure SQL output alias       : [traffic-output]
  (mapped to the fact_anomalies table)

INPUT / OUTPUT ALIASES YOU MUST CREATE IN THE PORTAL
----------------------------------------------------
  Input  alias : traffic-input   -> Event Hub  'traffic-events'
  Output alias : traffic-output  -> Azure SQL  table 'fact_anomalies'

NOTE ON COLUMNS
---------------
The Event Hub JSON does not carry a fact_traffic record_id (that id is an
IDENTITY generated by SQL). So this query leaves record_id NULL and only
fills the columns available in the stream. detected_at uses the event's
arrival time via System.Timestamp().

========================================================================
 QUERY (paste into the Stream Analytics Job -> Query editor)
========================================================================

WITH Classified AS
(
    SELECT
        location_id,
        avg_vehicle_speed,
        traffic_volume,
        accident_reported,
        System.Timestamp() AS detected_at,
        CASE
            WHEN accident_reported = 1 AND avg_vehicle_speed > 100 THEN 'ACCIDENT_RISK'
            WHEN avg_vehicle_speed > 120                          THEN 'SPEEDING'
            WHEN traffic_volume   > 700                           THEN 'CONGESTION'
            WHEN accident_reported = 1                            THEN 'ACCIDENT'
            ELSE 'NORMAL'
        END AS anomaly_type
    FROM [traffic-input]
)

SELECT
    location_id,
    anomaly_type,
    CASE
        WHEN anomaly_type = 'ACCIDENT_RISK' THEN 'HIGH'
        WHEN anomaly_type = 'SPEEDING' AND avg_vehicle_speed > 150 THEN 'HIGH'
        WHEN anomaly_type = 'SPEEDING'                            THEN 'MEDIUM'
        WHEN anomaly_type = 'CONGESTION' AND traffic_volume > 850 THEN 'HIGH'
        WHEN anomaly_type = 'CONGESTION' AND traffic_volume > 700 THEN 'MEDIUM'
        WHEN anomaly_type = 'CONGESTION'                          THEN 'LOW'
        WHEN anomaly_type = 'ACCIDENT'                            THEN 'HIGH'
        ELSE 'NONE'
    END AS severity,
    avg_vehicle_speed,
    traffic_volume,
    accident_reported,
    detected_at
INTO [traffic-output]
FROM Classified
WHERE anomaly_type <> 'NORMAL';

========================================================================
 HOW TO DEPLOY
========================================================================
1. Open the Stream Analytics Job  'asa-traffic-realtime'  in Azure Portal.
2. Under 'Inputs'  make sure an input alias 'traffic-input' points at the
   'traffic-events' Event Hub (JSON, UTF-8).
3. Under 'Outputs' make sure an output alias 'traffic-output' points at the
   Azure SQL database 'db-traffic', table 'fact_anomalies'.
4. Open 'Query', paste the query above, click 'Save query'.
5. Click 'Start' (or 'Restart' if it was already running) with output start
   time = 'Now'.
6. Run streaming_simulator.py locally so events flow into the Event Hub.
7. Anomaly rows will appear in fact_anomalies within a few seconds.
========================================================================
